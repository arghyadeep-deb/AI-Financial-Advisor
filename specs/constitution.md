# AI Advisory constitution

**Version** 2.1.0 · **Date** 2026-11-05

## I. Verified facts and exact money

Record money as exact decimal or integer minor units at all financial boundaries. Version canonical profile inputs, ledger rules, reports, and models. Keep observed values, estimates, user assumptions, and unavailable inputs distinct. Every published amount must be reproducible from an authorized versioned input snapshot.

## II. Code owns financial decisions

Deterministic tools calculate and validate cash flow, tax estimates, holdings, coverage, and constraints. An LLM may classify ambiguous descriptions or explain verified facts through a narrow structured contract. The application rejects unsupported amounts, products, and advice before publication. Model outages yield a limited report, an explicit degraded status, or a safe retry. The same constraints apply to normal results and fallbacks.

## III. Private and scoped by default

Every document, row, job, checkpoint, output, and export has an owner. Authorization is checked at each boundary, including resume, download, and worker execution. Use private encrypted storage and a separately managed signing secret. Trace payloads use a metadata allowlist. The first pilot uses synthetic data until deletion, isolation, and restoration checks pass. Record the approved retention and backup purge policy before enabling real uploads.

## IV. Durable, auditable workflows

Use LangGraph where a workflow needs checkpointing and review, beginning with monthly statements. Persist the business record in the application's database. Retries and concurrent requests must preserve correctness. Publication is transactional. A resumed run must never publish against stale source revisions. Chat, graph nodes, and integrations have narrowly scoped capabilities. Trades, payments, filing, and provider account linking are separate gated features.

## V. Testable incremental delivery

Keep FastAPI, the current browser entry point, and the current repository. Ship feature slices with synthetic acceptance fixtures, reproducible tests, explicit rollback, and operational metrics. Deterministic regression tests and release-blocking evaluations run without external services. LangSmith quality experiments use approved sanitized or synthetic examples. Product scope, authorization, and privacy gates override task completion.

## Governance

Each plan records how it meets these principles. Each review links requirements to tests and makes exceptions visible. Amend this file, bump its version, and update affected specs before implementing a deliberate policy change.

## VI. Product scope and lifecycle
The user decides when to implement. A planning task list is not an implementation instruction. Every release declares supported users, formats, periods, instruments, limits and incomplete states. Privacy deletion, recovery, resource budgets and usable error flows are core requirements before real data. Household sharing is explicit and revocable.

## VII. Evidence-based claims and allocation
Follow canonical financial rules and independent expected fixtures. Suitability, affordability and source coverage precede personalized proposals. Projections, education, research, drafts and observed balances are distinct. Professional titles do not confer authority on software; applicable provider/regulatory gates are enforced in code. No guarantee of returns or full professional replacement is implied.

## Delivery dependencies
Use [implementation order](implementation-order.md) for build stages and shared ownership. Privacy, operations and core UX are integrated with the monthly pilot and verified before real data. Planning documents do not assert implementation or successful tests.
